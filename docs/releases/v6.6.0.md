# v6.6.0: Sessions asking each other

Your sessions can talk to each other now. A session can ask another one a question, tell it
something, or ask it for a secret, on the same machine or across machines, and you see it on both
pages as a card.

Asking runs a read-only copy of the other session: it answers from its own conversation first, then
reads, greps and lists its own files if it needs to, and never runs anything, changes anything or
reads a secret file. The asking session gets the answer, plus any files it handed over, copied to its
own machine. When answering would need real work, like running tests or a command, you get an Allow
card, said out loud too, and the work only goes to that session once you allow it. Its answer then
comes back to the session that asked.

A tell is just information: it lands in the other session's queue labelled with who sent it, and a
session can't tell back the session whose message started its turn, so two of them can't loop.
Secrets always need your OK: on Allow, the value goes file to file into a temp file only the asking
session can read, and it's gone when that session stops (or after a day). It never goes through Voice
OS's state, logs, the page or voice. Names are matched on the asking session's machine first, and
when a name could mean more than one session, it's refused with the candidates instead of guessed.

The status recap and the "checkout needs you: …" line now run on Haiku 5.5: a bit faster, and a
tenth of the price. The router stays on Haiku 4.5, which is still faster on its slower turns.

A batch of debug-note fixes too. Switching to a session no longer replays what the meanwhile line
already said, a bare "yes" to *Switch there?* switches every time, and a meanwhile card you already
answered doesn't come back on the next tab. Barge-in stops Voice OS on your first real word, Discord
no longer cuts the start of a line after a pause, a long plan scrolls with its buttons always in
view, and a picture's link is only as wide as the picture.
